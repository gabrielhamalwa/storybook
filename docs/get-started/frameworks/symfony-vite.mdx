Storybook for Symfony & Vite is a [framework](../../contribute/framework.mdx) that makes it easy to develop and test [Symfony](https://symfony.com/) [Twig components](https://symfony.com/bundles/ux-twig-component) in isolation, with full support for [Stimulus](https://stimulus.hotwired.dev/) and the most common Symfony asset pipelines.

## Install

To install Storybook in an existing Symfony project, run this command in your project's root directory:

<CodeSnippets path="create-command.md" variant="new-users" copyEvent="CreateCommandCopy" />

You can then get started [writing stories](../whats-a-story.mdx), [running tests](../../writing-tests/index.mdx), and [documenting your components](../../writing-docs/index.mdx). For more control over the installation process, refer to the [installation guide](../install.mdx).

### Requirements

- PHP 8.2 or higher
- Symfony 6.4 or 7.0 with Twig and Symfony UX TwigComponent installed
- Vite 5 or higher
- The `storybook/symfony-bundle` Composer package installed and enabled

## Writing Symfony stories

Stories for Symfony/Twig components are written in CSF 3 with TypeScript. The `component` property of the meta export is the name of the Twig component as registered with `#[AsTwigComponent('Button')]`.

```ts title="Button.stories.ts"
import type { Meta, StoryObj } from '@storybook/symfony-vite';

type ButtonArgs = {
  label: string;
  variant?: 'primary' | 'secondary';
};

const meta = {
  title: 'Components/Button',
  component: 'Button',
} satisfies Meta<ButtonArgs>;

export default meta;
type Story = StoryObj<ButtonArgs>;

export const Primary: Story = {
  args: {
    label: 'Primary Button',
    variant: 'primary',
  },
};

export const Secondary: Story = {
  args: {
    label: 'Secondary Button',
    variant: 'secondary',
  },
};
```

The component template is rendered by the PHP backend, so any Stimulus controllers declared with `data-controller` in the template connect automatically when the story is rendered.

```twig title="templates/components/Button.html.twig"
<button
  type="button"
  data-controller="button"
  data-button-variant-value="{{ variant }}"
  class="btn btn-{{ variant }}"
>
  {{ label }}
</button>
```

## Supported component types

The bundle renders components through Symfony UX TwigComponent. The following identifier patterns are supported:

| Identifier     | Example  | Behavior                                                                                      |
| -------------- | -------- | --------------------------------------------------------------------------------------------- |
| Twig component | `Button` | Renders the component registered with `#[AsTwigComponent('Button')]` using the provided args. |

Plain Twig templates, Symfony UX Live Components, and controller fragments are planned for future releases.

## Supported asset pipelines

The PHP bundle auto-detects the installed asset pipeline by checking for known Symfony services. You can also override the detection in the bundle configuration.

| Pipeline        | Symfony package                 | Notes                                                       |
| --------------- | ------------------------------- | ----------------------------------------------------------- |
| Pentatrion Vite | `pentatrion/vite-bundle`        | Reads the `entrypoints.json` for the configured entrypoint. |
| Webpack Encore  | `symfony/webpack-encore-bundle` | Reads the Encore entrypoint lookup.                         |
| AssetMapper     | `symfony/asset-mapper`          | Reads the import map and eager entrypoint imports.          |
| None            | —                               | No styles or scripts are injected.                          |

By default, the bundle looks for an entrypoint named `app`. Change it in `config/packages/storybook/storybook.yaml`:

```yaml title="config/packages/storybook/storybook.yaml"
storybook:
  asset_pipeline: auto
  entrypoint: app
```

## Performance tips

### Keep the `storybook` environment minimal

Storybook boots a dedicated Symfony environment named `storybook`. Disable sessions, tests, and any other services you do not need when rendering components in isolation. A minimal `config/packages/storybook/framework.yaml` looks like this:

```yaml title="config/packages/storybook/framework.yaml"
framework:
  router:
    utf8: true
    strict_requirements: ~
  test: false
  session:
    enabled: false
```

### Use a fast PHP server

When `server` is omitted or set to `'auto'`, the framework detects FrankenPHP, RoadRunner, or the Symfony CLI and falls back to `php -S`. For the fastest day-to-day development, install FrankenPHP or the Symfony CLI and keep them in your `PATH`:

```ts title=".storybook/main.ts"
import type { StorybookConfig } from '@storybook/symfony-vite';

const config: StorybookConfig = {
  // ...
  framework: {
    name: '@storybook/symfony-vite',
    options: {
      symfony: {
        server: 'auto',
      },
    },
  },
};

export default config;
```

### Pre-warm the container cache

The first render after a container change can be slow because Symfony compiles the container for the `storybook` environment. Warm the cache once after installing or changing configuration:

```bash
APP_ENV=storybook bin/console cache:warmup
```

## FAQ

### How do I manually install the Symfony framework?

First, install the framework and the Composer bundle:

<CodeSnippets path="symfony-vite-install.md" />

Then, update your `.storybook/main.js|ts` to change the framework property:

<CodeSnippets path="symfony-vite-add-framework.md" />

Finally, register the bundle's routes in the `storybook` environment:

```yaml title="config/routes/storybook.yaml"
storybook:
  resource: Storybook\SymfonyBundle\Controller\StorybookController
  type: attribute
```

## API

### Options

You can pass an options object for additional configuration if needed:

<CodeSnippets path="symfony-vite-framework-options.md" />

The available options are:

#### `symfony`

Type: `object`

Configures the Symfony PHP backend and server lifecycle.

| Option        | Type     | Default                    | Description                                                                                  |
| ------------- | -------- | -------------------------- | -------------------------------------------------------------------------------------------- |
| `environment` | `string` | `storybook`                | Symfony environment used to boot the kernel.                                                 |
| `projectDir`  | `string` | `process.cwd()`            | Path to the Symfony project root.                                                            |
| `publicDir`   | `string` | `<projectDir>/public`      | Path to the public directory.                                                                |
| `server`      | `string` | `auto`                     | PHP server backend: `php`, `frankenphp`, `roadrunner`, `symfony-cli`, `existing`, or `auto`. |
| `serverUrl`   | `string` | —                          | URL to use when `server` is `existing`.                                                      |
| `port`        | `number` | random free port           | Port for the PHP server.                                                                     |
| `phpBinary`   | `string` | `php`                      | Path to the PHP binary.                                                                      |
| `console`     | `string` | `<projectDir>/bin/console` | Path to the Symfony console.                                                                 |

#### `builder`

Type: `Record<string, any>`

Configure options for the [framework's builder](../../api/main-config/main-config-framework.mdx#optionsbuilder). For this framework, available options can be found in the [Vite builder docs](../../builders/vite.mdx).
