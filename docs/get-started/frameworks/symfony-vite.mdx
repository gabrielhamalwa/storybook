Storybook for Symfony & Vite is a [framework](../../contribute/framework.mdx) that makes it easy to develop and test [Symfony](https://symfony.com/) [Twig components](https://symfony.com/bundles/ux-twig-component), plain Twig templates, controller fragments, and Symfony UX Live Components in isolation, with full support for [Stimulus](https://stimulus.hotwired.dev/) and the most common Symfony asset pipelines.

## Writing Symfony stories

Stories for Symfony/Twig components are written in CSF 3 with TypeScript. The `component` property of the meta export is the name of the Twig component as registered with `#[AsTwigComponent('Button')]`.

```ts title="Button.stories.ts"
import type { Meta, StoryObj } from '@storybook/symfony-vite';

type ButtonArgs = {
  label: string;
  variant?: 'primary' | 'secondary';
};

const meta = {
  title: 'Components/Button',
  component: 'Button',
} satisfies Meta<ButtonArgs>;

export default meta;
type Story = StoryObj<ButtonArgs>;

export const Primary: Story = {
  args: {
    label: 'Primary Button',
    variant: 'primary',
  },
};

export const Secondary: Story = {
  args: {
    label: 'Secondary Button',
    variant: 'secondary',
  },
};
```

The component template is rendered by the PHP backend, so any Stimulus controllers declared with `data-controller` in the template connect automatically when the story is rendered.

```twig title="templates/components/Button.html.twig"
<button
  type="button"
  data-controller="button"
  data-button-variant-value="{{ variant }}"
  class="btn btn-{{ variant }}"
>
  {{ label }}
</button>
```

## Component adapters

The PHP bundle can render four different kinds of components. By default, the `component` identifier is treated as a Symfony UX TwigComponent name, but you can override the adapter with `parameters.symfony.adapter` or let the bundle detect it from the identifier shape.

| Adapter             | `component` / `parameters.symfony`                                                                                                           | Behavior                                                                                               |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Twig component      | `component: 'Button'`                                                                                                                        | Default. Renders the component registered with `#[AsTwigComponent('Button')]` using the provided args. |
| Plain Twig template | `component: 'components/Alert.html.twig'` or `parameters.symfony.adapter: 'template'` with `parameters.symfony.template`                     | Renders a plain Twig template with the story args as variables.                                        |
| Controller fragment | `component: 'App\\Controller\\AlertController::fragment'` or `parameters.symfony.adapter: 'controller'` with `parameters.symfony.controller` | Renders a Symfony controller fragment.                                                                 |
| Live component      | `component: 'Notification'` with `parameters.symfony.adapter: 'live'` or `parameters.symfony.live: true`                                     | Renders a Symfony UX Live Component. Requires `symfony/ux-live-component`.                             |

The default Twig component example renders the `Button` component with the story args:

```ts title="Button.stories.ts"
import type { Meta, StoryObj } from '@storybook/symfony-vite';

type ButtonArgs = {
  label: string;
  variant?: 'primary' | 'secondary';
};

const meta = {
  title: 'Components/Button',
  component: 'Button',
} satisfies Meta<ButtonArgs>;

export default meta;
type Story = StoryObj<ButtonArgs>;

export const Primary: Story = {
  args: {
    label: 'Primary Button',
    variant: 'primary',
  },
};
```

A plain Twig template story can use the template path as the component identifier:

```ts title="Alert.stories.ts"
import type { Meta, StoryObj } from '@storybook/symfony-vite';

type AlertArgs = {
  message: string;
};

const meta = {
  title: 'Templates/Alert',
  component: 'components/Alert.html.twig',
} satisfies Meta<AlertArgs>;

export default meta;
type Story = StoryObj<AlertArgs>;

export const Info: Story = {
  args: {
    message: 'Saved successfully',
  },
};
```

A controller fragment story can use the controller reference as the component identifier, or pass it explicitly:

```ts title="AlertFragment.stories.ts"
import type { Meta, StoryObj } from '@storybook/symfony-vite';

type AlertFragmentArgs = {
  message: string;
};

const meta = {
  title: 'Fragments/Alert',
  component: 'App\\Controller\\AlertController::fragment',
} satisfies Meta<AlertFragmentArgs>;

export default meta;
type Story = StoryObj<AlertFragmentArgs>;

export const Info: Story = {
  args: {
    message: 'Saved successfully',
  },
};
```

A live component story sets the adapter explicitly. The `symfony/ux-live-component` package must be installed; otherwise, the render endpoint returns an error.

```ts title="Notification.stories.ts"
import type { Meta, StoryObj } from '@storybook/symfony-vite';

type NotificationArgs = {
  message: string;
};

const meta = {
  title: 'Live/Notification',
  component: 'Notification',
  parameters: {
    symfony: {
      live: true,
    },
  },
} satisfies Meta<NotificationArgs>;

export default meta;
type Story = StoryObj<NotificationArgs>;

export const Info: Story = {
  args: {
    message: 'Saved successfully',
  },
};
```

## Asset pipelines

The PHP bundle auto-detects the installed asset pipeline by checking for known Symfony services. You can also override the detection in `config/packages/storybook/storybook.yaml`.

| Pipeline        | `asset_pipeline` value | Symfony package                 | Notes                                                       |
| --------------- | ---------------------- | ------------------------------- | ----------------------------------------------------------- |
| Pentatrion Vite | `pentatrion_vite`      | `pentatrion/vite-bundle`        | Reads the `entrypoints.json` for the configured entrypoint. |
| Webpack Encore  | `encore`               | `symfony/webpack-encore-bundle` | Reads the Encore entrypoint lookup.                         |
| AssetMapper     | `asset_mapper`         | `symfony/asset-mapper`          | Reads the import map and eager entrypoint imports.          |
| None            | `none`                 | —                               | No styles or scripts are injected.                          |

The default `asset_pipeline: auto` setting detects the pipeline in this order: Pentatrion Vite, Webpack Encore, AssetMapper, then none. The bundle looks for an entrypoint named `app` by default:

```yaml title="config/packages/storybook/storybook.yaml"
storybook:
  asset_pipeline: auto
  entrypoint: app
```

For projects that do not use an asset pipeline, set `asset_pipeline: none` so the bundle returns no styles or scripts:

```yaml title="config/packages/storybook/storybook.yaml"
storybook:
  asset_pipeline: none
```

## Performance tips

### Keep the `storybook` environment minimal

Storybook boots a dedicated Symfony environment named `storybook`. Disable sessions, tests, and any other services you do not need when rendering components in isolation. A minimal `config/packages/storybook/framework.yaml` looks like this:

```yaml title="config/packages/storybook/framework.yaml"
framework:
  router:
    utf8: true
    strict_requirements: ~
  test: false
  session:
    enabled: false
```

### Use a fast PHP server

When `server` is omitted or set to `'auto'`, the framework detects FrankenPHP, RoadRunner, or the Symfony CLI and falls back to `php -S`. For the fastest day-to-day development, install FrankenPHP or the Symfony CLI and keep them in your `PATH`:

```ts title=".storybook/main.ts"
import type { StorybookConfig } from '@storybook/symfony-vite';

const config: StorybookConfig = {
  // ...
  framework: {
    name: '@storybook/symfony-vite',
    options: {
      symfony: {
        server: 'auto',
      },
    },
  },
};

export default config;
```

### Pre-warm the container cache

The framework runs `bin/console cache:warmup --env=storybook` automatically before starting the PHP server, so the first render does not pay the cost of container compilation. You can disable this behavior with `prewarmCache: false` if you prefer to manage the cache yourself:

```ts title=".storybook/main.ts"
import type { StorybookConfig } from '@storybook/symfony-vite';

const config: StorybookConfig = {
  // ...
  framework: {
    name: '@storybook/symfony-vite',
    options: {
      symfony: {
        prewarmCache: false,
      },
    },
  },
};

export default config;
```

When managing the cache manually, warm it once after installing or changing configuration:

```bash
APP_ENV=storybook bin/console cache:warmup
```

### How do I manually install the Symfony framework?

First, install the framework and the Composer bundle:

<CodeSnippets path="symfony-vite-install.md" />

Then, update your `.storybook/main.js|ts` to change the framework property:

<CodeSnippets path="symfony-vite-add-framework.md" />

```yaml title="config/routes/storybook.yaml"

  resource: Storybook\SymfonyBundle\Controller\StorybookController
  type: attribute
```

## API

### Options

You can pass an options object for additional configuration if needed:

<CodeSnippets path="symfony-vite-framework-options.md" />

The available options are:

#### `symfony`

Type: `object`

Configures the Symfony PHP backend and server lifecycle.

| Option         | Type      | Default                    | Description                                                                                  |
| -------------- | --------- | -------------------------- | -------------------------------------------------------------------------------------------- |
| `environment`  | `string`  | `storybook`                | Symfony environment used to boot the kernel.                                                 |
| `projectDir`   | `string`  | `process.cwd()`            | Path to the Symfony project root.                                                            |
| `publicDir`    | `string`  | `<projectDir>/public`      | Path to the public directory.                                                                |
| `server`       | `string`  | `auto`                     | PHP server backend: `php`, `frankenphp`, `roadrunner`, `symfony-cli`, `existing`, or `auto`. |
| `serverUrl`    | `string`  | —                          | URL to use when `server` is `existing`.                                                      |
| `port`         | `number`  | random free port           | Port for the PHP server.                                                                     |
| `phpBinary`    | `string`  | `php`                      | Path to the PHP binary.                                                                      |
| `console`      | `string`  | `<projectDir>/bin/console` | Path to the Symfony console.                                                                 |
| `prewarmCache` | `boolean` | `true`                     | Run `cache:warmup` for the configured environment before starting the PHP server.            |

#### `builder`

Type: `Record<string, any>`

Configure options for the [framework's builder](../../api/main-config/main-config-framework.mdx#optionsbuilder). For this framework, available options can be found in the [Vite builder docs](../../builders/vite.mdx).
